ENGINEERING PRINCIPLE

Separation of Responsibilities.

DUGN은 의료 업무 처리, AI 분석, 의료영상 관리, 결과 파일 저장 및 데이터 연동의 책임을 각 서비스에 분리한 시스템입니다.

전체 팀 시스템을 이해하고, 개인 담당 영역에서는 데이터 정합성, 접근 제어 및 의료 데이터 연동을 중심으로 백엔드 기능을 구현했습니다.

위 기술 구성은 팀 전체 시스템을 기준으로 설명하며, 개인 구현 범위와 실제 코드는 Backend & API 및 Validation 섹션에서 별도로 설명합니다.

How It Works

01
Transaction Atomic

관련 데이터 변경을 하나의 트랜잭션으로 묶어 처리하며, 예외 발생 시 변경 사항을 롤백할 수 있도록 구성합니다.

02
Select For Update

조회한 기존 예약 슬롯 행에 잠금을 적용하여 트랜잭션이 진행되는 동안 동일 행의 동시 수정 위험을 줄입니다.

03
Conflict Validation

기존 활성 예약과 변경 대상 슬롯을 비교하여 예약과 근무 일정의 충돌을 검사합니다.

Implementation Outcome

근무 일정 변경 과정에서 기존 예약을 고려하고, 예약 슬롯의 일관성을 유지하기 위한 백엔드 처리 구조를 구현했습니다.

def released_result(patient, result_id):
                    return (
                        ResultRelease.objects.select_related(
                            "signoff",
                            "signoff__doctor",
                            "signoff__doctor__department",
                            "report",
                            "report__report_version",
                            "report__report_version__medical_result",
                        )
                        .filter(
                            report__report_version__medical_result_id=result_id,
                            report__report_version__medical_result__patient=patient,
                            report__status__in=[Report.Status.ACTIVE, "FINAL"],
                            release_status=ResultRelease.ReleaseStatus.RELEASED,
                            withdrawn_at__isnull=True,
                            signoff__signoff_type="FINAL",
                        )
                        .order_by("-released_at", "-id")
                        .first()
                    )

How It Works

01
Object-level Access Control

환자 식별 정보와 결과 ID를 함께 검증하여 다른 환자의 결과가 조회되지 않도록 데이터 조회 조건을 제한합니다.

02
State-based Validation

최종 서명, 공개 상태, 공개 철회 여부를 함께 검사하여 조회 가능한 결과를 결정합니다.

03
Signed Snapshot

서명 시점의 보고서 및 첨부 결과를 스냅샷으로 관리하여 이후 AI 분석 결과가 변경되더라도 확정된 보고서와 구분합니다.

04
Query Optimization

select_related를 사용하여 관련 객체를 함께 조회하고, 반복적인 관계 객체 조회로 발생할 수 있는 추가 쿼리를 줄이도록 구성했습니다.

Implementation Outcome

AI 분석 완료와 환자 결과 공개를 분리하고, 의료진이 확정한 결과를 공개 조건에 따라 환자에게 제공하는 백엔드 구조를 구현했습니다.

의료영상 처리 과정의 개념도이며 실제 환자 영상은 포함하지 않았습니다.

PROBLEM

CT 영상과 Segmentation Mask의 배열 축 순서 및 공간 정보가 일치하지 않으면, 생성된 3D 구조의 위치와 방향이 원본 의료영상과 달라질 수 있습니다.

ENGINEERING DECISION

Mask를 CT 기준 공간에 정렬하고, Spacing, Direction, Origin을 반영하여 Mesh의 정점 좌표를 의료영상의 물리적 좌표계로 변환했습니다.

02 / SPATIAL COORDINATE ALIGNMENT

Voxel to Physical Space.

배열 인덱스와 실제 의료영상 공간 좌표의 차이를 고려한 데이터 변환 과정입니다.

INPUT COORDINATES

Voxel Coordinates

배열 인덱스 기반의 영상 데이터 좌표

OUTPUT COORDINATES

Physical Coordinates

영상의 간격, 방향 및 원점을 반영한 좌표

Spacing

각 Voxel 사이의 물리적 간격을 반영합니다.

Direction

의료영상의 공간 방향을 반영합니다.

Origin

의료영상의 물리적 시작 위치를 반영합니다.

PHYSICAL COORDINATE TRANSFORMATION P = O + D × (S ⊙ I)
P : Physical Position O : Origin D : Direction S : Spacing I : Voxel Index
03 / CORE IMPLEMENTATION

Mesh Reconstruction & GLB Generation

Segmentation Mask에서 표면 Mesh를 생성하고 공간 좌표를 변환하는 실제 구현 코드입니다.

ai/ccta_rendering.py 
spacing_xyz = image.GetSpacing()

            vertices, faces, _normals, _values = marching_cubes(
                mask,
                level=0.5,
                spacing=(
                    spacing_xyz[2],
                    spacing_xyz[1],
                    spacing_xyz[0],
                ),
            )

            vertices = vertices[:, [2, 1, 0]]

            direction = np.asarray(
                image.GetDirection(),
                dtype=float,
            ).reshape(3, 3)

            origin = np.asarray(
                image.GetOrigin(),
                dtype=float,
            )

            vertices = vertices @ direction.T + origin

            mesh = trimesh.Trimesh(
                vertices=vertices,
                faces=faces,
                process=False,
            )

            if name in {"heart", "aorta"}:
                trimesh.smoothing.filter_laplacian(
                    mesh,
                    iterations=5,
                    volume_constraint=True,
                )

How It Works

01
Mask Resampling

CT 영상과 Mask의 공간 정보가 일치하도록 CT 기준으로 Mask를 정렬합니다. 이 과정은 Mesh 생성 이전에 수행됩니다.

02
Marching Cubes

3차원 Mask의 경계면에서 정점과 삼각형 면을 추출하여 표면 Mesh를 생성합니다.

03
Axis Reordering

NumPy 영상 배열의 ZYX 축 순서와 의료영상 공간 정보의 XYZ 축 순서 차이를 고려하여 정점 좌표의 축을 재배열합니다.

04
Physical Coordinate Transformation

Spacing을 반영한 정점에 Direction과 Origin을 적용하여 의료영상의 물리적 공간 좌표로 변환합니다.

05
Selective Mesh Smoothing

심장과 대동맥 Mesh에는 Laplacian Smoothing을 적용합니다. 관상동맥과 석회화 구조에는 동일한 평활화를 적용하지 않습니다.

06
GLB Export & Storage

생성한 3D 데이터를 GLB 파일로 변환하고, RustFS에 저장하여 의료진 서비스에서 활용할 수 있도록 연결합니다.

Implementation Outcome

CT와 Mask의 공간 좌표 차이를 고려한 3D Mesh 생성 및 결과 파일 저장 파이프라인을 구현했습니다.
